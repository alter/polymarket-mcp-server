# Polymarket 技术实现详解

## 核心技术组件

**条件代币框架（CTF）**
系统使用 Gnosis 的 CTF 对所有事件结果进行代币化，采用 ERC-1155 标准实现为"股票代币"。这些代币完全抵押，每个事件最多支持 256 个结果。每个预测获得一个唯一的条件 ID，派生自三个参数："预言机地址、问题 ID 和结果槽数量"。

## 订单机制

三种订单类型：
- **市价订单**：立即执行
- **限价订单**：指定价格执行  
- **AMM 订单**：现已弃用

当前系统使用 CLOB（中央限价订单簿）或 BLOB（二元限价订单簿），描述为"混合去中心化订单簿，专业运营商负责订单撮合"。

## 智能合约

CTFExchange.sol 合约（约 100 行）通过依赖关系管理仓位：BaseExchange.sol、Auth.sol、Assets.sol 等。三个主要函数执行交易：`fillOrder()`、`fillOrders()` 和 `matchOrders()`，只能由授权运营商调用。

## 费用结构

费用计算基于输出资产。对于二元预测，费用是对称的，确保买卖双方收取相等费用。

## 预言机系统（UMA）

去中心化预言机通过五阶段流程提供结果：
1. **声明**：预测进入预言机，关联争议奖励
2. **挑战期**：最终确认前的争议机会
3. **争议**：协议参与者挑战结果
4. **投票**：UMA 代币持有者通过提交/揭示投票解决争议（防止勾结）
5. **结算**：最终区块链确认

博弈论激励机制：
- 提案者质押抵押品，如被争议则面临损失风险
- 挑战者也需提交保证金，正确则获得奖励
- UMA 投票者因正确解决争议而获得质押奖励
- 所有参与方都面临不诚实的经济惩罚

## 三组件架构集成

**CTF**：管理结果组合和用户仓位表示  
**CLOB**：Polymarket 专有的订单撮合和限价订单系统  
**UMA**：通过博弈论争议解决提供无需信任结算的去中心化预言机

该分层架构通过结合专业协议贡献来提供复杂的预测市场功能，强调机构级基础设施所需的技术复杂性。
