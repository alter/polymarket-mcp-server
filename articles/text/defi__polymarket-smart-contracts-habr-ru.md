# Polymarket: Полный технический разбор

## Обзор

Polymarket — децентрализованная платформа рынков предсказаний на блокчейне Polygon. Система использует некастодиальные кошельки: "протокол не хранит приватные ключи пользователей и не может получить доступ к их активам."

## Архитектура кошелька пользователя

**Прокси-кошельки**: Новые пользователи выбирают между существующими EOA-аккаунтами (MetaMask, Coinbase, WalletConnect) или аутентификацией через Magic Link по email. Кошельки деплоируются через фабрики смарт-контрактов как мультисиги 1-of-1, обеспечивая полный контроль пользователя и возможность пакетных транзакций.

## Основы предсказательного рынка

Каждый рынок событий сформулирован как бинарный вопрос. Пользователи "голосуют", покупая токены-акции (стандарт ERC-1155), обеспеченные USDC. Победители получают вознаграждение из взносов проигравших участников.

## Условный токен Framework (CTF)

Polymarket использует CTF от Gnosis, поддерживающий до 256 исходов на событие. Каждое предсказание получает **conditionId**, производный от хеша:
- Адрес оракула
- QuestionId (идентификатор, задаваемый создателем)
- OutcomeSlotCount

CTF реализует механизмы **splitting** (разделение позиций на отдельные исходы) и **merging** (объединение исходов в одну позицию).

## Три сценария исполнения сделок через смарт-контракт

### 1. BUY vs SELL (P2P-обмен)

Оператор находит два ордера и упаковывает их в транзакцию. Смарт-контракт выполняет прямой P2P-перевод токенов YES от одного участника к другому. Игра с нулевой суммой: общее предложение токенов не изменяется. Расход Gas минимален.

### 2. BUY vs BUY (минтинг новых токенов)

Смарт-контракт списывает pUSD с обоих участников, блокирует их как залог и вызывает функцию `_mint`, создавая YES и NO токены. Затем отправляет YES первому участнику и NO второму.

### 3. SELL vs SELL (сжигание — Merge)

Смарт-контракт забирает YES у одного участника и NO у другого. Вызывает `_merge`, уничтожает пары YES+NO и разблокирует pUSD из казны, распределяя средства пропорционально вкладу.

## CLOB/BLOB — Гибридный ордербук

Система состоит из двух частей:

**Оффчейн**: Backend-оператор, отслеживающий ордера, выполняющий матчинг и формирующий данные для рыночных ордеров.

**Ончейн**: Смарт-контракт, принимающий данные сопоставления ордеров, выполняющий расчёты и исполняющий ордера на блокчейне.

Пользователь создаёт ордер, формируя структуру данных, подписанную приватным ключом по стандарту EIP-712. Пока ордер не исполнен, он хранится off-chain, что позволяет обновлять и отменять его без газовых транзакций.

## Ключевые контракты

- **ctf-exchange-v2**: Основной контракт исполнения ордеров (~100 строк), поддерживаемый модульными зависимостями: BaseExchange.sol, Auth.sol, Assets.sol
- Три основные функции: `fillOrder()`, `fillOrders()`, `matchOrders()` — доступны только авторизованным операторам

## Оракул UMA

UMA использует оптимистическую модель: данные считаются корректными, пока не оспорены. Контракт запрашивает итог, участник публикует результат и вносит залог, затем открывается окно для оспаривания.

После окончательного определения результата на контракте оракула, он отправляет запрос `reportPayouts` на контракт CTF. Держатели акций вызывают метод `redeemPositions`, который сжигает акции и возвращает залог пропорционально позиции.

## Блокчейн и комиссии

Polymarket работает на Polygon — сети второго уровня для Ethereum. Преимущества:
- Минимальные комиссии (менее $0.01 за транзакцию)
- Скорость (подтверждение за 2-3 секунды)
- Прозрачность (все ордера видны в блокчейне)
- Безопасность — смарт-контракты исключают манипуляции платформы

## Итог

Polymarket — сложная гибридная система, где ордербук работает off-chain для скорости и удобства, а финансовые расчёты (минтинг, сжигание токенов, выплаты) выполняются смарт-контрактами на блокчейне Polygon — прозрачно и без участия посредников.
